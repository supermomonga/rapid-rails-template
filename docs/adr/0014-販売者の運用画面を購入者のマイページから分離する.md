# 販売者の運用画面を購入者のマイページから分離する

## Context and Problem Statement

購入者の契約管理と販売者の設定・売上管理が同じマイページのメニューに混在し、重複する横並びナビゲーションと役割の不明確さが生じていた。ユーザーは管理画面と同様に「販売者画面」から独立したメニューへ移動する構成を指定した。

## Decision Drivers

* 購入、販売、運営の作業対象を明示する
* ホストの認証・権限と共通のレイアウト・タブ・アイコンを再利用する
* 販売者登録前も案内を提供し、他の販売者の情報にアクセスさせない

## Considered Options

* マイページ内で販売者リンクをグループ化する
* Engine内に販売者専用のnamespaceとレイアウトを設ける

## Decision Outcome

Engine内に`Billing::Merchant`を設け、`/merchant/billing`で販売者の概要、プラン、契約・売上・返金、プロフィール・送金先を管理する。購入者の`/account/billing`、運営者の`/admin/billing`と区別する。販売者画面はホストの`layouts/with_menu`を再利用し、メニュー項目はHeroiconsと現在地を表示する。関連する表示の切り替えは`with_tab`へ統一する。販売者の作業は引き続きUser所有のMerchantProfileとAction Policyで認可する。

### Consequences

* Good, because 購入者メニューに販売用の設定を混在させず、操作対象と戻り先が分かる。
* Good, because 既存のresponsive navigation、タブパネル、ページ操作領域の規約を共有できる。
* Bad, because 販売者向けのroute helperと画面URLの移動が必要になる。旧経路は提供しない。

### Confirmation

購入者・販売者・管理者の権限と導線、他販売者データの非表示、売上の集計範囲をテストする。日本語sampleで空状態、通常状態、設定不足、入力エラー、desktop/mobileのタブ接続・メニューアイコン・overflowを検証する。
